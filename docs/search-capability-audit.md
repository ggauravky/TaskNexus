# Global Search Capability Audit

Phase C adds one authenticated, bounded search surface over seven existing domains. It does not merge marketplace `tasks` with project `project_tasks`, and it does not reuse any application, applicant, evidence, or submission read path.

| Domain | Existing route and owner | Existing visibility and query behavior | Phase C adapter decision |
| --- | --- | --- | --- |
| Teams | `GET /api/teams`; `teamService` / `teamData` | Public discovery is restricted to active public teams; `scope=mine` can include private memberships. Existing `visibility/status` indexes support the catalog predicate. | Add a projected, sorted, `limit(5)` public-only method. Membership and administrator status never widen global results. |
| Projects | `GET /api/projects`, `GET /api/teams/:teamId/projects`; `projectService` / `projectData` | Team-scoped and “my projects” reads can include authorized non-public work. Effective public visibility requires both a public active parent Team and a public non-archived Project. | Add a cross-team aggregation with public Project and parent Team predicates, projection, deterministic sort, and database limit. No participants, repositories, or evidence. |
| People | `GET /api/people`; `discoveryService` | Discovery enforces active accounts, public/discoverable profiles, self exclusion, and either-direction blocks, then performs richer bounded ranking and evidence/project expansion. `discoverable/visibility` indexes support privacy filtering. | Reuse the privacy/block helpers, but not `discoverPeople` wholesale: the palette needs five lightweight rows and must not materialize or decorate rich evidence. |
| Hackathons | `GET /api/hackathons`; `hackathonService` | Ordinary catalog reads are public and non-archived. Administrators can use existing explicitly authorized private catalog scopes. Existing `visibility/status` indexes support the catalog predicate. | Add a projected search using the same role visibility policy and fixed database limit; omit registrations, teams, submissions, and participation state. |
| Opportunities | `GET /api/opportunities`; `opportunityService` | Public catalog uses the existing open/published/unexpired filter. Candidate/application decoration is a separate path. Existing `status/published_at` indexes support the catalog predicate. | Add a projected search using `openFilter`, deterministic sort, and `limit(5)`. Never load native applications, applicants, or candidate state. |
| Organizations | `GET /api/organizations`; `opportunityService` | Returns active public organization summaries. Existing `status/name` indexes support the catalog predicate. | Add a projected active-only search with fixed database limit and no memberships, invitations, or applicant data. |
| Marketplace tasks | `GET /api/tasks`; `taskService` / `taskData` | Role lists are bounded, but freelancer discovery intentionally includes unassigned work. Compound client/status and freelancer/status indexes support participant predicates. | Add a strict search-context method: client-owned, freelancer-assigned, or administrator inspection scope only. Never reuse the available-task query and never read `ProjectTask`. |

All Phase C adapters escape user text before constructing regular expressions, anchor queries with the owning domain's authorization/catalog predicate, select only serializer inputs, use deterministic ordering, and apply the five-row limit in MongoDB. The API computes no totals and accepts no caller-controlled result limit.
